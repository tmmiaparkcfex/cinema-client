# 0.4.1 界面与缓冲验证版

基于 0.4.0（4b9b5d627ac71a217ec2ac92b317ef5654c7a534）继续开发。此版本用于核对演示图版式和复测播放，尚不能作为“全部页面与全部功能完成”的运营版本。

- 首页、片库、详情、收藏/历史、下载、个人页和设置改为共享海报配色、半透明面板。详情使用影片真实标题图和分集剧照。底栏为首页、片库、我的；会员和管理后台仍按用户要求暂缓。
- 横屏播放器将传输控制放在底部，时间置于进度条两侧；横屏选集、音轨、字幕、倍速等面板从右侧打开。沿用原生 libmpv/FFmpeg，优先硬件解码。
- 将前向缓存上限设为 64 MiB、后向 16 MiB，读取目标 30 秒，恢复播放缓冲目标 3 秒；关闭内核追加式磁盘缓存；网络读取超时调整至 40 秒，避免与本机分段转发的等待窗口失配。用户可见的连续缓冲看门狗仍为 40 秒。
- 增加本机缓冲等待时长、位置和缓冲余量记录，以及内核缓存设置读回。日志不包含播放地址和账号请求头。
- 默认倍速、自动下一集设置接到真实本机偏好；“看过”单独保存，不覆盖分集续播进度。
- 补入手机号、验证码、密码、重置密码、资料、安全、帮助、反馈、隐私和通知界面。缺失服务尚未对接，不会模拟登录成功、短信发送、上传、反馈成功或云同步。

尚未完成：全部演示页逐项核对；竖屏内嵌播放、系统画中画和投屏；演员作品页；分享、消息和弹幕等流程；下载批量管理与仅 Wi-Fi 约束。当前片库筛选限已读取的影片。上述项目没有被视为用户取消的需求。

## 已知复测条件

用户设备为 iPhone 13 Pro / iOS 18.7.7。用户反馈《仙逆》第165集在 Wi-Fi 下偶尔转圈、轻度发热。接口存在普通主线与普通备用两份 4K HEVC 文件，平均码率约 7.8/8.2 Mbps；尚不知道当时实际选用哪条线路，也没有该次播放的吞吐或解码日志。因此超时失配属于代码检查发现的潜在原因，不能视为已经复现或定位全部原因。

组件测试和模拟器不能证明真机零发热、零卡顿。GitHub 原生测试新增对打包的 iOS libmpv 设置与读回缓存参数的检查；它也不替代 4K 真机播放复测。

## 真机复测

1. 用个人 Apple ID 为 unsigned IPA 签名，保留原应用标识以延续本机数据。无需向开发方提供 Apple ID 密码。
2. 同一 Wi-Fi、同一亮度，播放《仙逆》第165集主线和备用；记录转圈时间点与次数，观察画面和声音是否同时恢复。不要同时充电，以减少额外变量。
3. 播放器右上角“播放信息”查看实际解码、丢帧和系统热状态；设置 → 关于影院可复制最近诊断日志。
4. 热状态严重升高、声音继续而画面停住、长时间连续转圈均仍是需要处理的问题，不能以编译或测试通过代替验收。
