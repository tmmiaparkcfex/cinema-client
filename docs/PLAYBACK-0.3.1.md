# 0.3.1 播放修复

## 容量错误

夸克可能先以 `code=0` 接受异步转存，再在任务查询中返回 HTTP 200、`code=32003`、`capacity limit[{0}]` 和 `status=3`。旧客户端没有识别英文容量错误，因而显示通用转存失败，并一直保留失败任务登记。

现在使用 `member` 返回的总量和已用量提前检查资源是否装得下，提示所需、剩余空间；仍识别转存阶段的容量错误，以覆盖并发占用导致的容量变化。只移除已明确失败的任务登记，不删除账号已有文件。

## 原画缓冲

同一条快传 CDN 地址的开放式 Range 请求与有界 Range 请求存在明显吞吐差异。新增设备内 `RangePlaybackSource`，让原生播放器通过回环地址读取四路、每段最多 1 MiB 的 HTTPS 上游数据。HTTP Range、Content-Range、文件总长度和顺序保持一致；该层不转码、不经过 vod-web 或开发者服务器。

取流层限制为回环绑定和随机路径，跨来源重定向移除凭据。退出、取消、重试和资源释放时关闭监听及上游连接。

## 验证

- 使用相同普通播放账号复现容量不足，修正后在转存提交前停止并提示容量。
- 对照实际快传链接，重复开放式请求仍慢；设备内取流实现的有界并行请求改善吞吐。原始测试数据保存在用户本地，凭据与地址未提交仓库。
- 自动化测试覆盖容量拒绝、英文异步错误、失败任务恢复、原文件保护、完整字节流、随机拖动、后缀范围、HEAD、无效范围、错误 CDN 响应、凭据重定向隔离与监听释放。
- 实测网络对照在 Windows 主机完成，不等于已完成真实 iPhone 的 Wi-Fi 连续播放、HDR 或功耗验收。iPhone 仍需安装更新后复测。
