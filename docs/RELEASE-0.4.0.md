# 0.4.0 开发与验收记录

基线：`codex/playback-capacity-buffering-fix`，提交 `5c9de59958538e51e5d8d47cbe1e970ab775301f`，版本 0.3.1+5。
开发分支：`codex/immersive-native-cinema`，版本 0.4.0+6。

## 目标与事实

- 目标设备由用户提供：iPhone 13 Pro，iOS 18.7.7。片库来源全部为 4K。
- 用户报告 0.3.1 严重发热，偶尔画面停顿数秒且声音继续。
- 原工程已经使用原生 media_kit / libmpv，而非浏览器播放器。继续保留成熟内核及设备内账号流程。
- 已确认代码开销：播放进度 / 缓冲事件触发整页刷新；默认输出纹理没有按手机显示尺寸限制。
- 以上事实不能证明它们是全部故障原因。编码格式、硬解回退、HDR / DV 特性、网络和热降频仍需要真机数据区分。

## 开发内容

用户界面根据原型延展：海报取色背景、手动精选轮播、浅色胶囊导航、影片简介、分季 / 分组剧集卡片、演职员资料、搜索与本地搜索历史、片库筛选、收藏 / 观看记录、账号与接口设置。

播放沿用原生引擎，保留音轨、字幕、外挂字幕、倍速、比例、锁定、续播和换线。新增按屏幕匹配的显示纹理、控制栏刷新预算、实际解码 / 掉帧 / 热状态查询。减少显示输出像素不会改写、转码或换成低清文件。

下载为实际文件下载：单任务执行、队列、暂停、原文件断点续传、完成记录恢复、本地离线播放和删除。CDN 地址及账号头不持久化。文件路径由资源 ID 哈希派生，只删除应用拥有的文件。使用现有严格 Range 代理验证每段字节位置与长度。

后台和播放期间暂停下载；不会宣称已实现 iOS 后台下载。原型中会员、支付和运营后台按照后续要求不开发。没有真实服务支持的弹幕、云同步等入口没有伪装成可用功能。

## 自动验证

测试包含：现有资源解析 / 分季 / 账号隔离 / Cookie / 转存清理 / 播放控件；新增原画显示尺寸与刷新预算、暂停 Range；下载字节一致性、断点续传、持久化恢复、删除边界、后台取消和租约释放。

真实界面由 Flutter 组件测试渲染。它能验证版式，不能代表 iPhone 上已成功解码 4K 视频。GitHub Actions 的原生 iOS 编译与模拟器测试需以本分支实际运行结果为准。

## 真机复测

1. 同一部 4K 影片，记录版本、文件编码 / 码率和发生停顿的时间段。
2. 先确认播放信息里的“实际解码”。若为软件解码，记录该状态及文件信息。
3. 播放 15–20 分钟，检查画面 / 声音、拖动、切集、切线、锁屏 / 回前台。
4. 在正常播放与发生停顿时分别查看掉帧和系统热状态；可在“关于影院”复制过滤后的诊断日志。
5. 单独测试下载暂停 / 重开 / 断网恢复，以及关闭网络后播放完成的本地文件。

这些是待执行的真机验收，不作为已通过结果。
