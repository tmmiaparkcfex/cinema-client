# 客户端架构与观看链路

## 分层

```text
Flutter UI
  ├─ 首页/详情/搜索/片单/我的
  ├─ 自定义播放器控件
  └─ 本地片单与观看进度
数据层
  ├─ VodApi：/api/home /api/list /api/search /api/detail /api/resource
  ├─ HomeCache：仅缓存最小目录字段，不缓存分享/播放信息
  └─ LocalStore：SharedPreferences 中的片单与进度
设备内夸克桥接
  ├─ InAppWebView：只负责用户本人登录
  ├─ QuarkPlaybackService：分享 token、目录定位、专用目录、转存、直链、清理
  ├─ QuarkAccountStore：iOS Keychain / Android Keystore
  └─ quark_temp_files.json：只记录本应用创建且待清理的 fid
播放层
  ├─ media_kit Player
  ├─ media_kit_video Video
  └─ 运行时 HTTP 请求头（Referer/User-Agent/Cookie）
```

## 正常观看流程

1. 应用启动：读取本机缓存目录，优先显示上次首页；后台重新请求 `/api/home`。
2. 用户选择作品：`/api/detail` 返回作品资料、线路、季集和每集资源描述。
3. 播放前检查设备内是否有夸克会话；没有则打开登录页，由用户自己登录。
4. `QuarkPlaybackService` 按资源描述：
   - 请求分享 `stoken`；
   - 在所选分享内定位目标文件（按文件 ID 和大小，避免只靠文件名）；
   - 查找/创建根目录下 `.cinema-client` 专用目录；
   - 将该文件转存到专用目录；
   - 取得短时直链和必要请求头。
5. 生成 `QuarkPlaybackLease`，交给 media_kit 的 `Player.open(Media(..., httpHeaders: ...))`。
6. 播放器通过 Range 读取，显示真实缓冲/时长/音轨/字幕；进度每 10 秒和退出时写入本机。
7. 离开播放器：删除本应用刚转存的 fid，并从临时登记文件移除。
8. 下次启动：尝试清理因崩溃/强退仍留在登记表中的本应用文件。

## 设备内边界

- 影视接口只提供目录和资源描述；不提供视频流。
- 客户端不把夸克 Cookie 发给影视接口。
- 客户端不调用服务端下载代理。
- 客户端不使用开发者的夸克账号。
- 夸克登录网页是唯一的 WebView；视频播放由原生 libmpv 完成。

## 文件生命周期

| 阶段 | 应用行为 | 是否触碰用户原文件 |
| --- | --- | --- |
| 分享定位 | 只读列出所选分享目录 | 否 |
| 专用目录 | 在用户网盘根目录查找/创建 `.cinema-client` | 否 |
| 转存 | 只把当前选中文件保存到专用目录 | 否 |
| 播放 | 使用临时直链 + 观看者 Cookie | 否 |
| 退出 | 删除本次响应中的新 fid | 否 |
| 异常中断 | 下一次启动重试删除登记 fid | 否 |
| 异常清理失败 | 保留登记，不冒充已清理 | 否 |

### 已知限制

- 直链可能短时失效；播放器错误面板提供“重新获取地址”，会重新走授权链路。
- 崩溃强退时无法保证即时删除，只保证下次启动/手动清理重试。
- 70 GB 级文件会短期占用观看者网盘配额；不做服务端代播或后端缓存。
- 专用目录是应用创建的目录，但不排除用户手动把其他文件放进去；清理只按本应用保存的 fid 删除，不按目录全删。

## 状态与错误

- 网络/超时：API 层带超时；首页有缓存。
- 播放准备：75 秒总超时，可取消；取消后迟到的租约会被释放。
- 播放中：40 秒缓冲看门狗；触发后停止等待并出现重试/换线。
- 正常结束：剧集有下一集则 8 秒倒计时自动播放；没有下一集显示播放结束，不显示为错误。
- 字幕、音轨只在真实轨道列表中选择；没有在线字幕搜索入口，避免假承诺。
